# 译点 · 自建 AI 翻译

一个不订阅、不限额的 Chrome 翻译扩展：划词翻译 + 整页双语对照，翻译请求直接发到你自己的 AI 接口。

替代 MaxAI 的思路很简单——那类扩展卖的是「帮你接好模型」，但你已经有模型了，缺的只是一个好用的外壳。

---

## 一、安装

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录（`ai-translator`）
4. 装好后会自动打开设置页

> 不要删掉或移动这个文件夹，解压版扩展是直接从磁盘读取的。

---

## 二、配置

在设置页填三项就够了：

| 项 | 说明 |
|---|---|
| Base URL | OpenAI 兼容接口地址，**不要**带 `/chat/completions` |
| API Key | 只存本机，不同步云端；本地服务可留空 |
| 模型 | 见下表 |

内置预设（选完自动填 Base URL 和模型）：

| 服务商 | Base URL | 推荐模型 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| Anthropic | `https://api.anthropic.com` | `claude-3-5-haiku-latest` |
| Gemini | `https://generativelanguage.googleapis.com` | `gemini-2.0-flash` |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen2.5:7b` |

### 服务商和模型不用你自己查

设置页做了三件事：

1. **认服务商** —— 粘 Base URL 时实时显示「识别为 DeepSeek · OpenAI 兼容 · 实际请求 https://api.deepseek.com/v1」
2. **补路径** —— 只填 `https://api.deepseek.com` 就行，`/v1` 自动补。各家的差异（智谱是 `/api/paas/v4`、OpenRouter 是 `/api/v1`、百炼是 `/compatible-mode/v1`）都内置了，共 22 家
3. **拉模型** —— 点「拉取模型」，向接口的 `/models` 读真实可用列表，自动把 embedding、whisper、tts、rerank 这些非对话模型排到后面并标注

模型框是可搜索的下拉，也可以直接手打。列表拉不到的服务商（少数不开放 `/models`）不影响使用，手写模型名照样能翻译。

### 看模型的响应速度和可用性

模型「能不能用」和「快不快」是两件事，都可能随时变（尤其是聚合网关）。设置页给每个模型测速：

| 操作 | 结果 |
|---|---|
| 模型框右侧「测速」 | 测当前模型，显示 `首字 420ms · 总 1.1s · 约 3.1 字/秒 · 可用` |
| 模型列表里的「测全部」 | 并发 3 个、每个最多等 15 秒，逐个测对话模型，失败的直接标红 |
| 列表右侧徽标 | 绿色 < 1.5s，黄色 < 5s，红色更慢；失败显示「失败」，超时显示「超时」 |
| 「按速度排序」 | 快的排前面，测不通的沉到最后 |

测速发的是**流式、`max_tokens: 8`、提示词「只回复 OK」**的极短请求，几乎不产生费用。之所以用流式，是因为翻译时你真正感觉到的是**首字延迟**（点下去多久开始出字），而不是总耗时。

结果按「接口地址 + 模型」缓存，关掉设置页再打开还在；接口地址一改就作废。

弹窗里也有「测速」，不用进设置页。划词翻译的卡片底部也会带上这一次的耗时，比如 `首字 380ms · 总 1.4s · 约 21 字/秒`。

### 协议不用你操心

三种协议的请求格式、鉴权位置、响应结构都不一样：

| 协议 | 路径 | 鉴权 | system 放哪 |
|---|---|---|---|
| OpenAI 兼容 | `/chat/completions` | `Authorization: Bearer` | messages 里 |
| Anthropic | `/v1/messages` | `x-api-key` | 顶层 `system` 字段 |
| Gemini | `/v1beta/models/{model}:generateContent` | `?key=` 查询参数 | `systemInstruction` |

你只要填 Base URL 和模型名，协议自动认。识别逻辑是四层：

1. **显式指定** —— 你在设置里选了哪个就用哪个，不回退
2. **记忆** —— 上次这个「地址+模型」用哪个协议成功的，直接用
3. **启发式** —— `anthropic.com` 或 `claude-*` → Anthropic；`generativelanguage.googleapis.com` 或 `gemini-*` → Gemini；其余 → OpenAI 兼容
4. **回退** —— 猜错时看错误码：400/401/403/404/405/422 换下一种协议再试，429 和网络错误不重试（换协议救不了限流和断网）

响应解析更进一步，**不依赖协议**：`choices[].message.content`、`content[].text`、`candidates[].content.parts[].text` 三种形状哪个有内容就读哪个。所以就算你用的是个奇奇怪怪的代理，只要它吐出这三种形状之一，也能用。

填完点 **测试连接**，再点 **保存**。

### 提升翻译质量的两个开关

- **温度**：调低到 `0` ~ `0.2`。翻译是确定性任务，温度高了模型会自作主张改写。
- **附加要求**：比换模型更有用。例如技术文档写：

  > 术语保留英文原文并用括号加中文；不要使用「您」，统一用「你」；代码块和命令保持原样。

## 三、用法

| 操作 | 方式 |
|---|---|
| 划词翻译 | 选中文字 → 点浮出的「译」 |
| 右键翻译 | 选中文字 → 右键 → 翻译「…」 |
| 翻译正文 | `Alt+T`，或点扩展图标 → 翻译正文，或点网页右侧的「译」 |
| 翻译整页 | `Alt+W`，或弹窗里「翻整页（含侧栏）」 |
| 还原原文 | 再按一次 `Alt+T`（`Alt+W` 也行） |
| 仅译文 / 双语 | `Alt+Y`，或弹窗里「仅译文 / 切回双语」 |

整页翻译默认是**双语对照**：译文插在每段原文下方，带一条淡蓝色竖线，原文不动。适合精读和校对，不适合截图分享；要截图就按 `Alt+Y` 切成**仅译文**，再按一次切回来。

**仅译文**不是把原文变成透明留在原地（那样一段长文字会空出一大片白，译文看着像「掉到了后面」），而是**直接把原文的文字换成译文**：元素、class、字号、字重、颜色、行高、缩进一个都不动，所以看起来就像这个页面本来就是中文的。带图片/视频、嵌套列表这类不能整块换的，才退回「原文透明 + 译文插在下方」。这个选择会记住，换页也生效。

段落里带超链接（`by <a>作者名</a>`、`Read <a>this article</a>` 这种）时，换字是**按文本节点分别换**的：`<a>`、`<b>` 这些标签原样留在原地，链接照样能点，译文分别落在各自的位置上。做法见下面的「带链接的段落」。此外，页面里常见的卡片容器（如 Nexus 的 `<div class="tile">` 包裹标题+作者+摘要）不会被当成一整段翻译——容器本身跳过，里面的标题、作者、摘要等小块各自独立翻，这样布局完全保持原样，不会互相串位。

**导航栏、按钮里的文字也会被替换**。像 Nexus 顶栏的 `Games / Mods / Collections`（结构是 `<div><button><span>Games</span><svg/></button></div>`）、页脚的 `News / All games`（`<li><a>News</a></li>`）、卡片的标题和作者名，翻译都会**落在链接/按钮自己的文字位置**，不是另外插一个独立的译文块——所以译文照样能点，图标也不会丢。

万一模型不听话、没原样保留 `{{1}}` 这类分段标记，扩展会自动**把每个文本节点单独再翻一遍**，而不是放弃——所以链接文字一定会被替换成译文，不会停在英文上。

### 只翻正文，不翻边角料

`Alt+T` 会先找「装着最多正文」的容器（`article` / `main` / `[role=main]` / 常见正文类名），只翻那一块：

- 导航栏、页脚、侧边栏、广告位不动，长文页面不会白花钱，也不会把菜单翻成一堆奇怪的名词
- 认不出正文（比如首页列表、论坛帖子），或者正文几乎就是整页时，自动退回翻整页
- 就是想连导航一起翻，用 `Alt+W`（会把当前译文清掉整页重翻）

> 判断逻辑写在 `pickScope()` 里：候选容器的正文块数 ≥ 3、字数占全页 < 80% 才算数，取正文块字数最多的那个。

划词结果是**逐字出现**的（流式），不用干等整段返回；整页翻译也是译完一段插一段，所以第一段译文通常一两秒就能看到。

### 动态加载的页面也能翻

单页应用（SPA）、无限滚动、展开评论区这类页面，正文是翻完那一刻之后才慢慢长出来的。翻完整页后扩展会继续盯着 DOM：

- 新出现的段落**自动接着翻**，不用再按一次快捷键
- **先翻看得见的**：按下时优先翻当前视口内和附近的段落，一轮最多 40 段，剩下的后台接着补。长文不会让你干等整页，第一屏几乎立刻有译文
- 代码块（`<pre>` / `<code>`）、输入框、可编辑区域、标了 `translate="no"` 或 `.notranslate` 的节点一律跳过
- 再按一次 `Alt+T` 会**立刻**还原：连已经发出去、还没回来的译文也会被丢弃，不会还原完又冒出来

不想要自动续翻，去设置页「整页翻译」把**动态加载的新内容自动翻译**关掉，就只翻按下那一刻页面上已有的正文。

### 快捷键改不了？

去 `chrome://extensions/shortcuts` 改，`Alt+T` / `Alt+W` / `Alt+Y` 都可能和别的扩展或输入法冲突。

| 快捷键 | 作用 |
|---|---|
| `Alt+T` | 翻译正文 / 还原 |
| `Alt+W` | 翻译整页（含导航、侧栏、页脚） |
| `Alt+Y` | 双语对照 ⇄ 仅译文 |

### 页面还没加载完就按了？

以前会**没反应**——内容脚本还没注入，消息发过去没人收。现在不管什么时机按都行：

1. 后台发现没人接，**就地注入内容脚本**再发一次，所以刷新过、刚打开、脚本还没跑起来的页面都能翻
2. 页面还在加载时，会先等 `load`（最多 6 秒）再开始翻，免得漏掉后面才出来的正文
3. 页面本身不允许注入（`chrome://`、扩展商店、PDF 阅读器）时，工具栏图标上会亮一个红色的 `!`，弹窗里也会写明原因——不再是点了没反应

### 扩展页面出现红色「错误」？

点开看一眼具体内容。如果是 `Permissions policy violation: unload is not allowed in this document`，那是 1.7.1 及更早的内容脚本在页面里注册了 `unload` 监听（被站点的 Permissions-Policy 拦下），1.7.2 已改成 `pagehide`，不会再出现——这类历史记录点「全部清除」即可。

这也提示了一件事：改了代码之后一定要在 `chrome://extensions` 里点 ↻ 重新加载，再刷新已经打开的标签页，否则跑的还是旧脚本。

## 四、它和 MaxAI 的区别

| | 译点 | MaxAI |
|---|---|---|
| 体积 | 约 40 KB | 61.8 MB / 609 个文件 |
| 模型 | 你选 | 它定 |
| 计费 | 你付 API 成本 | 订阅制，免费额度有上限 |
| 代码 | 全部可读可改 | 混淆打包 |
| 数据 | 只发往你配置的接口 | 经它自己的服务中转 |
| 登录 | 不需要 | 需要账号 |

**成本参考**：一页 50 段的文章约 3–5k 输入 token、2–4k 输出 token，`deepseek-chat` 大约 **不到 1 分钱**。同一段文字第二次出现直接读本地缓存，不重复计费。

## 五、实现要点

```
manifest.json          MV3 清单
background.js          配置 / 接口调用 / 缓存 / 右键菜单 / 快捷键
content/content.js     划词气泡、结果卡片、整页注入（Shadow DOM 隔离）
content/content.css    译文样式（!important 防站点覆盖）
popup/                 工具栏弹窗
options/               设置页
```

几个设计上的取舍：

- **批量翻译**：整页按每批 8 段打包成一次请求，用 `<<<1>>>` 编号让模型对齐段落。比逐段请求省 token、也快得多。
- **解析兜底**：模型偶尔会漏编号或忽略格式，代码会挑出缺的段落单独重试，仍失败就留空，不会把错位译文插到错误段落。
- **缓存**：以「模型 + 目标语言 + 原文」为键，上限 2000 条，按最近使用淘汰。
- **同语言跳过**：中文页面翻成中文时，已经符合的段落不会重复请求。
- **UI 隔离**：气泡和卡片挂在 Shadow DOM 里，页面 CSS 改不动它，也不会被页面全局事件吞掉。
- **流式输出**：内容脚本用 `chrome.runtime.connect` 开长连接，后台边收 SSE 边把增量回传。三种协议的增量字段（`choices[].delta.content`、`delta.text`、`candidates[].content.parts[]`）统一处理后，卡片是逐字长出来的。
- **边写边插**：整页翻译时，一段译文的结尾只有等下一个 `<<<n>>>` 出现才能确认。所以判定规则是「后面跟着新编号才算写完」，写完的段落立刻插进页面——不用等整批返回。
- **已缓存段落不再进请求**：整批翻译会先把命中缓存的段落直接吐出去，只把没缓存的发给模型，而且**保持原始编号位置**，不会错位。
- **吐字后不换协议**：如果模型已经开始输出才报错，就不会再试其他协议了——换了会把前半句重复一遍。
- **测速**：`probeModel()` 发一个流式、`max_tokens: 8`、提示词「只回复 OK」的请求，用 `AbortController` 卡 15 秒超时，量出首字延迟、总耗时和出字速度。设置页并发 3 个跑，结果按「地址 + 模型」缓存。
- **按需注入**：`sendToTab()` 先直接发消息，失败就 `chrome.scripting.executeScript` 注入内容脚本（含 CSS）、重新 ping 确认，再发一次。内容脚本自带 `window.__MXT_ACTIVE__` 守卫，重复注入是空操作。清单里 `run_at` 用 `document_end` 而不是 `document_idle`，让脚本在慢页面上更早到位。
- **动态内容**：翻完整页后用 `MutationObserver` 盯着 `body`，DOM 安静 700ms 才开始处理，一轮最多 40 段，处理完还有剩就排下一轮，直到补完。自己插入的译文节点带 `data-mxt`，会被过滤掉，所以不会自己触发自己（也就不会无限循环）。
- **不重复插入**：每轮都重新扫 DOM，`alreadyTranslated()` 用「紧邻的下一个节点是不是我插的译文」判断，同一段绝不会插两份。翻过的容器会打上 `mxt-orig`，里面的子元素下一轮直接跳过，不会越翻越碎。框架重建 DOM 导致的重复翻译有本地缓存兜底，不会再花一次钱。
- **不只翻 `p` / `li`**：很多站点的卡片标题是 `<a>`、摘要是 `<div>`，只按标签挑会漏一大片。所以还会再做一遍「纯文本容器」扫描：标签是 `div / span / a / strong …`、里面没有段落或列表之类的块级结构、并且不在已翻的块里面，就当一段翻。父级是 flex/grid 时译文插到容器内部（否则会变成被挤扁的另一个格子），其余情况插在它后面。
- **视口优先**：按下 `Alt+T` 时按「离视口多远」排序，当前可见的一屏先翻，其余由后续轮次补齐。
- **还原要立刻生效**：每轮翻译持有一个 `runToken`，还原时把它作废，所以在途的流式结果回来后会被直接丢掉——否则还原之后译文还会陆续冒出来。
- **正文识别**：`pickScope()` 在主内容选择器里挑「正文块字数最多」的容器（至少 3 个块、字数占全页 < 80%），锁定后只在这个容器里找段落。容器被 SPA 换掉后会自动重新识别。
- **仅译文 = 原地换字**：不给原文加 `color: transparent`（那会把节点里所有行内文字一起弄透明），而是把原文的子节点整体挪进一个 `DocumentFragment`（不克隆，事件监听和节点状态都还在），塞一个译文文本节点进去——元素本身、class、行内样式完全不动，所以布局和样式跟原文一模一样。译文节点只是加上 `mxt-hidden` 藏起来，切回双语时把 fragment 放回去、节点显出来。`<h2><a>标题</a></h2>` 这种只换 `<a>` 里的字，链接还在。带图片/视频、嵌套列表、表单控件的块不换字，退回 `display: none` + `-webkit-text-fill-color: transparent` 的兜底。
- **带链接的段落**：整段换字会把段落里的 `<a>` 一起吃掉，链接就没法点了。所以遇到「段落里还有 `<a>`」「自己被包在 `<a>`/`<button>` 里」「里面有 `<svg>` 图标」的块，发请求前用 `{{1}} {{2}}` 给每个文本节点打上位置标记（提示词里要求原样保留），译文回来后 `splitInlineMarks()` 按标记把文字切回去，**只改每个文本节点的字**：`<a>`、`<b>`、`<svg>` 结构一个不动，链接可点、按钮可按、图标不丢、行内格式还在，字号行高也还是页面自己的。模型没保住标记（数量对不上）时，`retranslateParts()` 会**把每个文本节点单独再翻一遍**，保证链接文字一定被换成译文，而不是停在原文上。
- **换字目标要在插入译文之前算好**：`swapTargetOf()` 靠「这个块是不是只有一个 `<a>`」来判断该把文字换进链接里。如果先插了译文节点再判断，`children.length` 就变成 2，`<li><a>News</a></li>` 会认不出那个 `<a>`，文字就停在一个不能点的独立块里。同理 `canSwap()` 要忽略我们自己插的 `.mxt-trans`——不然单段文字的块会因为「里面有个 div」而放弃换字。
- **SVG 图标不翻**：`svg` 里的 `<text>` 是图标/logo 的一部分（站点常见的搜索框、收藏夹图标），`innerText` 会把它算进正文，翻出来就变成「图标上写着中文」。所以 `svg` / `math` 整个跳过，只翻它旁边的文字。
- **右侧快捷图标**：和气泡/卡片一样挂在 Shadow DOM 里，`position: fixed` 贴右边缘，鼠标移上去才完全显形；点击等于 `Alt+T`。
- **不注册 `unload`**：越来越多站点（以及 Chrome 的默认策略）禁掉 `unload` 事件，内容脚本一旦注册就会被记成 `Permissions policy violation: unload is not allowed in this document`，并出现在扩展的「错误」列表里。每 3 秒的 `housekeeping` 定时器改用 `pagehide` 停、`pageshow` 接。
- **流式看门狗**：接口「不吐字也不断开」是最容易把页面卡死的情况。`callOnceStream()` 里有个「多久没收到新内容」的定时器（默认 30 秒，`settings.stallMs` 可覆盖），超时就中止请求并报「等了太久没等到输出」；内容脚本这边还有一层 45 秒没收到后台消息就放弃的兜底，保证页面不会永远停在「翻译中」。

## 六、已知限制

- 自动识别覆盖 **OpenAI 兼容 / Anthropic / Gemini** 三种协议。其他私有协议（比如某些厂商的签名鉴权）仍需改 `background.js` 里的 `buildRequest()`。
- **流式已支持**，但**没有中止按钮**：整页翻译发起后只能等它跑完，或者刷新页面。
- **模型列表**依赖服务商开放 `GET /models`。少数服务商（或自建代理）不提供，会提示拉取失败，手动输入模型名即可。
- **测速是粗测**：只发一个 8 token 的请求，受当时网络抖动和网关排队影响。要更准就多测几次看趋势；「测全部」会真实打到上游，68 个模型大约花十几秒到一分钟。
- 虚拟滚动（只渲染可见行的长列表）只能翻到它真正渲染出来的行；滚回去再滚回来会再插一次译文，但内容命中本地缓存，不会再请求模型。
- 不处理 PDF 内置阅读器、图片文字、`<canvas>` 里渲染的文本。
- **双语模式**下译文是整段纯文本插在原文下方，原文那一行的行内加粗/链接不会被复制到译文里（原文本身完全不动，链接照常可点）。**仅译文**模式下带链接的段落会按文本节点分别换字，链接和 `<b>` 之类都留着。卡片容器（如 Nexus 的 `<div class="tile">`）不会被当成一整段翻译，里面的标题、作者、摘要等小块各自独立翻，布局完全保持原样。
- **模型不守规矩时要多花一次请求**：带链接的段落用 `{{1}}` 标记切段，如果模型没原样保留标记，扩展会把每个文本节点单独再翻一遍（每个节点一次请求）。链接多的页面会因此多花一些额度。
- **卡片/画廊的文字靠「纯文本容器」启发式识别**：标题、摘要、分类这类 `div`/`a` 能翻到，但按钮、tab 之类的短标签也可能被一起翻；如果某个站点整块区域被误当成一段，按 `Alt+W` 重翻或告诉我站点名加例外。
- **仅译文**模式下换字是按「整段」做的：段内的行内格式（加粗、行内链接）在这个模式下会被译文顶掉（切回双语或还原就回来）；带图片/视频、嵌套列表、表单控件的块不换字，退回「原文透明 + 译文插在下方」。带 `<a>` 的段落例外——按文本节点分别换，链接和 `<b>` 之类都留着；模型没保住 `{{k}}` 标记时会逐个文本节点再翻一遍。
- **正文识别是启发式的**：论坛、文档站大体没问题；遇到把正文塞进 `<div class="xxx-content">` 又不在候选名单里的站点，`Alt+T` 可能只翻到一部分，按 `Alt+W` 翻整页即可。
- 划词翻译单次上限 8000 字符。

## 七、可以做但没做

按价值排序，想要哪个直接说：

1. **中止按钮 + 失败重试** —— 中途能停，失败的段落单独重跑
2. **术语表** —— 指定「OpenCode 不翻译成开放代码」，比写提示词硬约束更可靠
3. **悬浮球悬停翻译** —— 不用划词，鼠标停 1 秒就译（右侧快捷图标已经有了，这个是悬停触发）
4. **输入框翻译** —— 在聊天框里打字，`Ctrl+Enter` 先翻成目标语言
5. **多引擎对比** —— 同一段同时问两个模型，并排看
6. **私有协议适配** —— 自定义请求模板（URL / Header / Body 都自己写）
