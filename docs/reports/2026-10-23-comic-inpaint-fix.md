# 漫画「没有擦字」修复（2026-10-23）

用户报障：译文能出来，但原图上的原文还在，看起来像没擦字。

## 结论：擦字算法没问题，是三条重画路径把「同源副本」弄丢了

跨域漫画图片的原图是**污染画布**，`getImageData` 会抛异常。所以扩展会先用后台
`mxt:fetchImage` 取回字节、在页面里造一张 `data:` 副本，擦字时画这张副本。

问题在于：**这张副本（`drawable`）没有在每一条重画路径上传下去**。丢了之后
`readPixels` 失败 → `renderTranslated` 返回 null → 安静退回浮层覆盖。
表现就是「有译文、没擦字」。

三处都丢：

| 位置 | 原代码 | 后果 |
| --- | --- | --- |
| 翻回翻过的一张 | `paintOverlays(img, rec.items)` 写死浮层 | 切换图片 = 退回浮层，擦字只在第一次翻译出现过一次 |
| 点「擦字版」 | `applyToImage(img, rec.items)` 少传第三个参数 | 跨域站上点擦字版毫无反应，用户以为按钮坏了 |
| `state.done.set` | 只存 `{items, at}` | 没有副本可传，前两条修了也没得用 |

## 改法

1. 两处 `state.done.set` 都存 `drawable`。
2. 缓存命中分支改走 `applyToImage(img, rec.items, rec.drawable)`，并加测试禁止
   在这里调用 `paintOverlays`。
3. 切模式时传 `rec.drawable`。
4. 擦不动时**说明原因**（新增 `note()`，追加一行提示，不清空译文列表）。
5. 模型只给译文不给坐标时也提示，否则同样是「图没变化」。

## 验证

- `tests/comic-paint-mode.test.ts`（6 条）守接线：缓存命中和切模式必须带 `drawable`，
  `state.done` 必须存副本，`note` 不能清空列表，样式里要有对应位置。
  这组 bug 的特点是**丢了不报错**，只能靠盯源码，所以要测试盯着。
- 真实站点实测（MangaDex 章节 + Agnes `agnes-3.0-flash`）：**10/10**
  - 新增断言 `擦字重绘（不是浮层覆盖）` → `{"total":1,"inpainted":1,"textLayers":0}`
    区分「盖一张 data: 新图」（真擦了）和「盖一堆 div」（只是浮层）。
- `npm run verify`：560 tests / 32 files；构建 15 文件 342.6 KB；密钥扫描 86 文件干净。

## 教训

「擦字」有两条独立的失败路径——算法出错，和副本丢失。前者会报错或画面明显不对，
后者完全静默，而且只在「第二次看到这张图」时才出现。默认值 `inpaint` 让首屏看起来
正常，掩盖了后续所有路径的问题。

顺带记录：`note()` 这种「说明为什么降级」的提示，比让功能静默降级重要得多。
用户报的是「没有擦字」，实际有三四种不同成因，没有提示就只能靠猜。
